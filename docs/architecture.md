# 架构边界

## 核心服务

核心服务是唯一必须运行的进程，负责：

- 用户认证和 Session
- 组织和成员
- 角色和权限
- 大模型配置和对话
- Feature 注册、审计边界和运行入口

即使没有任何已启用的业务功能，核心服务也必须能够正常启动。核心启动流程不得导入 `features/` 或扩展工作区中的生成代码。

账号使用唯一用户名登录，邮箱只作为可选资料保留。成员必须具备姓名和联系方式，联系方式不限定格式，可以是手机号、微信号或其他文本。组织创建后，创建者自动成为所有者。

组织是可嵌套的树结构，顶级组织的 `parent` 为空，子组织通过 `parent` 指向上级组织。用户只能把新组织挂到自己有成员关系且拥有 `organization.manage` 权限的组织下；旧版本已有组织迁移为顶级组织。当前成员关系仍以组织为边界，不会因为父子关系自动继承子组织成员权限。

权限以菜单和操作为维度组织。前端根据当前组织返回的权限显示菜单，Vue 路由进入和 Django API 接口还会再次校验权限；隐藏菜单不被视为安全边界。角色配置页面按照菜单分组展示权限，组织数据始终以当前 Session 组织为范围。

## 声明式 Feature

常见业务需求保存在 `features` 应用中。Feature Manifest 描述字段、列表、表单、详情和操作，Vue 通用页面根据定义渲染。

AI 只能通过应用服务提议或创建 Manifest，不得执行 SQL、修改 Python 导入、安装依赖、运行 Shell 或编辑核心文件。

每条 Feature 记录都绑定一个组织。后端服务在执行查询和写操作前统一检查当前 Session 的组织成员关系和权限。

Feature 的发布、停用和记录增删改都会留下组织审计记录。损坏的 Manifest 只会在校验或访问时返回错误，不会阻塞核心服务启动。

## 文件与 Excel 基础能力

`core/filekit` 是为未来业务和 AI 生成代码预留的文件能力模块，包含安全文件保存和 `.xlsx` / `.xlsm` 解析。它只返回文件描述或 JSON 友好的表格数据，不创建业务数据表，也不自动生成导入页面。

上传文件统一保存到 `data/uploads`，使用随机文件名，并限制分类目录、扩展名和大小。Excel 解析限制行列数量，按首行表头生成列名，日期转换为 ISO 文本，不执行公式、宏或任意代码。具体业务必须先校验当前组织权限，再把解析结果映射到自己的 Feature 字段并执行字段校验。

当前不提供通用文件上传菜单或公开上传接口。后续 AI 生成客户、资产等业务时，直接复用 `core.filekit`，由生成的业务模块决定上传页面、字段映射和导入结果。

## 代码扩展

无法用声明式 Feature 表达的复杂业务，留到后续阶段通过代码扩展承载。扩展位于核心目录之外，经过草稿、依赖检查、静态检查、测试和启用流程。

未来的扩展运行器可以为每个扩展提供独立虚拟环境、SQLite 数据库、端口、PID 和日志。扩展异常不能阻止核心服务启动。同进程插件只适用于可信且经过审查的代码，不能视为任意 AI 代码的安全沙箱。

## 运行规则

- 各平台的 `start` 脚本只启动核心服务。
- Windows 使用 PowerShell 和 BAT；macOS/Linux 使用 Bash。
- Linux 登录自启动使用用户级 systemd；macOS 使用 LaunchAgent；Windows 使用任务计划程序。
- Feature 发布后由通用渲染器直接读取，不需要重新编译或重启核心服务。
- 核心数据库迁移由核心项目维护，不从 AI 对话生成迁移。
- API Key 只保存在服务端，并在数据库中加密保存。
- 默认监听地址是 `127.0.0.1`。

## 品牌与图标

站点设置保存在核心数据库中，由具备 `organization.manage` 权限的管理员编辑。Logo 通过统一文件上传边界保存；登录页匿名读取展示配置，设置更新接口仍需要管理员权限。

前端统一使用 Element Plus 图标，并在 `frontend/src/styles.css` 提供 `.app-icon`、`.app-icon--nav` 和 `.app-icon--accent` 样式。图标按钮需要提供 `title` 和 `aria-label`，不额外引入业务图标包。
